# MHD volume statistics

Ticket volumes by month, type, priority and theme, with the counting caveats that make the raw numbers misleading.

Last reviewed: 23 September 2026
Sources: Jira MHD, 2025-09-01 to 2026-09-23

Source: moneyme1.atlassian.net, project **MHD (MME Help Desk)**. Read-only harvest, 23 September 2026.

## Method and counting caveats

Read this before quoting any number below.

- **Exact counts** (marked *exact*) come from JQL `searchResultMode: count` run against the full population. They are reliable.
- **Sampled figures** (marked *sample*) come from a working set of 3,785 issues pulled down and aggregated locally. That set is the union of: the earliest 200 issues of each month in the window, plus the 100 most recent matches for each of about 23 theme keyword searches. It is **not** a random sample and it over-weights themed tickets. Use it for shape, not for precision.
- `text ~` in Jira is a word-based, stemmed match, not a phrase match. Multi-word searches such as `text ~ "statement of account"` behave inconsistently and returned 1,756 hits, which is plainly matching the individual words. Treat every multi-word theme count as indicative only. Single-token searches such as `text ~ "SOA"` and `text ~ "arrears"` are trustworthy.
- `text ~` searches summary, description **and** comments, so a ticket is counted under a theme if any investigator merely mentioned the word.
- British and Australian spellings do not match the system's own. `text ~ "amortisation"` returns 11 tickets; `text ~ "Amortization"` returns 183. Search both spellings.
- `text ~ "DDR"` returns only 5, and `text ~ "trust migration"` returns 0. Neither is a reliable handle for its topic.
- Resolution-time figures are calendar days between `created` and `resolutiondate`, computed on the sampled set only.

## Headline

| Measure | Value |
| --- | --- |
| Total MHD issues created in the window | **10,218** *exact* |
| Average per month | roughly 790 |
| Issues in a Done status category | 5,550 *exact* |
| Issues with no `resolution` value set | 6,816 *exact* |

The gap between those last two rows matters. 5,550 issues sit in a Done status category but only 3,402 of them carry a resolution. Statuses such as **Deployment Completed** close a ticket without ever setting `resolution`, so any report built on `resolution = Done` undercounts completed work by a wide margin. Use `statusCategory = Done` instead.

## Components

**No MHD issue in the sampled set carries a component.** The component field is unpopulated across the project. Product and system are instead encoded informally in the summary line, typically as a prefix: `APY |`, `CRD |`, `MME |`, `PL |`, `Freestyle |`, `SOC1`, `SPL`, `[G1 - Database Release]`, `[HOR - CODE Release]`. Any future categorisation work has to parse the summary or start populating components.

## Resolution time (*sample*, n=1,320 resolved issues)

| Cohort | n | Median | Mean | Same day | Within 1 day | Within 5 days | 90th percentile |
| --- | --- | --- | --- | --- | --- | --- | --- |
| All types | 1,320 | 1 day | 9.2 days | 39% | 55% | 70% | 26 days |
| Problem | 964 | 1 day | 8.2 days | 42% | 56% | 70% | 13 days |
| Service Request | 209 | 1 day | 7.7 days | 43% | 71% | 82% | 28 days |

The median is misleadingly good. The distribution is bimodal: most tickets are answered the same day or the next, then a long tail drags the mean to nine days. A large part of the tail is not investigation time but the **five business day auto-close**, which resolves a ticket when the reporter stops replying. MHD-36071, MHD-36075, MHD-36283, MHD-35875, MHD-35381, MHD-35159 and MHD-36446 all carry a `resolutiondate` set by that automation rather than by anyone confirming a fix. Resolution time in MHD is closer to "time until the conversation stopped" than "time to fix".

That is the single largest category of hands-on work the team does and it is invisible in the Problem counts above, because each child is linked by `Blocks` or `Cover` rather than typed as a data fix.

## What could not be verified

- Exact per-status and per-label counts across the full 10,218. The status and label tables above are sampled.
- Whether the `Threat Intelligence Review` and other automated feeds have ever been excluded from any existing MHD reporting.
- First-response time. The `created` to first human comment interval was not extracted; `Automation for Jira` posts an acknowledgement within minutes on most tickets, so any naive first-response metric would be meaningless.
- Reporter and assignee distribution. Fields were collected but not aggregated in this pass.
